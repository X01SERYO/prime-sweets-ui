# PDR-005 — PC viewport uses the available screen

**Status:** Proposal
**Language:** English
**Scope:** Shell and seller screens on a PC viewport.
**Document role:** Product design requirement. Not a description of the running UI.

Business rules stay in the Core API. This document does not add a screen, a role, or a business action.

## 1. Purpose

On a PC, the seller's screens should use the width and height of the window. A small laptop and a large monitor must not show the same narrow column with the same type size and empty space on both sides.

The phone layout stays the capture layout already defined in [PDR.md](./PDR.md) §2. Width still does not add or remove a business action.

## 2. What the seller sees

1. On a small laptop (about 1280 px wide) the content fills the window, with a modest margin, instead of stopping near 1024–1216 px.
2. On a larger monitor the content keeps growing with the window, up to a ceiling that still leaves a margin. Tables and forms stretch; they do not stay a fixed card in the middle.
3. Titles, body text, table text, and controls grow with the viewport inside the PC range, and stay readable on the small laptop. They do not jump to a phone-sized type on a desktop window.
4. The four-section navigation (Por mayor, Detal, Cargue, Productos) stays a sidebar on PC and a bottom bar on phone. Only its spacing and type scale.
5. Invoice print layout is unchanged: 70 mm page, not the screen layout.

## 3. Out of scope

New screens, a tablet product, user-agent detection, a density setting, and changing print CSS.

## 4. Acceptance criteria

- At 1280 px, 1440 px, and 1920 px wide, the main column is wider than the current `64rem` / `76rem` cap and leaves a visible margin.
- Type in the shell and in the main tables is larger at 1920 px than at 1280 px.
- At a phone width (≤ 640 px) the layout, bottom navigation, and 16 px form fields stay as they are today.
- No route, label, or action appears or disappears because of width.
