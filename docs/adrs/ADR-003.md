# ADR-003 — Product administration is a catalog screen

**Status:** Proposed
**Date:** 2026-11-01
**Document role:** Architecture decision for the UI feature in [PDR-003](../pdrs/PDR-003.md). Not a description of the running UI.
**Depends on:** [ADR-001](./ADR-001.md) and the API [ADR-003](../../../prime-sweets-api/docs/adrs/ADR-003.md).

## Context

The home screen is organized by delivery day: **Nueva venta**, the week, **Entregas**, and **Cargue**. Product administration is not part of that day. The API owns persistence and Alegra. The button **Productos** already sits to the left of **Nueva venta** and does nothing yet.

## Decision

| UI behavior | Module |
|---|---|
| Home button **Productos** | `sales` home view links to the catalog route |
| List, create, update, and logical delete | `catalog` |

The client never calls Alegra.

## Rejected alternatives

### Putting product actions on the delivery-day row

Rejected. Entregas and Cargue belong to the selected day. Products do not.

### A catalog module that calls Alegra

Rejected. The browser talks only to the API.

## Consequences

- Delivery-day documents do not specify this screen. See [PDR-002](../pdrs/PDR-002.md).
