# ADR-004 — Fluid PC shell, phone layout unchanged

**Status:** Proposed
**Date:** 2026-11-16
**Document role:** Architecture decision for [PDR-005](../pdrs/PDR-005.md). Not a description of the running UI.
**Depends on:** [ADR-001](./ADR-001.md) and SPEC §4.1.

## Context

`.shell main` is `width: min(64rem, 100%)`, and from `min-width: 64rem` it becomes `min(76rem, 100%)`. A 1280 px laptop and a 1920 px monitor therefore share one column of about 1216 px. Type sizes are fixed `rem` values. The phone rules at `max-width: 40rem` (14 px body, 16 px inputs) are the narrow class and should stay.

SPEC §4.1 already forbids a third device role and forbids viewport checks inside domain, use cases, and HTTP adapters.

## Decision

Scale the PC presentation in CSS only.

| Mechanism | Rule |
|---|---|
| Content width | In the narrow class, `.shell main` is full width with `0.75rem` of side padding. From `48rem`, cap it at `min(calc(100% - 8rem), 1440px)`, centered beside the sidebar. |
| Type | On `min-width: 64rem`, set `html { font-size: clamp(16px, 0.35vw + 12px, 20px); }` so rem-based type grows with the window. Do not change the `max-width: 40rem` phone block. |
| Ownership | Shell rules live in `src/app/styles.css`. A feature stylesheet changes only its own overflow or column rules when a table still clips. No module reads `window.innerWidth`. |
| Navigation | Keep the existing sidebar / bottom-bar switch. Do not add a breakpoint between phone and PC. |

## Rejected alternatives

### More fixed breakpoints (1280, 1440, 1920)

Rejected. Three hard widths repeat the current problem between the steps.

### A React hook that sets a scale class

Rejected. SPEC §4.1 keeps viewport branching out of application code. CSS can express width and type.

### Removing the max width entirely

Rejected. A wide window then stretches tables and forms to the edges. `1440px`, centered, leaves the side space empty.

## Consequences

- Implementation follows [SPEC-005](../specs/SPEC-005.md).
- Architecture, model, and flows stay unchanged until the CSS lands. This ADR does not describe runtime.
