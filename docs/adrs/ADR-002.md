# ADR-002 — Delivery day as the client's organizing unit

**Status:** Proposed (revised 2026-11-01)
**Date:** 2026-11-01
**Document role:** Architecture decision for the UI feature in [PDR-002](../pdrs/PDR-002.md). Not a description of the running UI.
**Depends on:** [ADR-001](./ADR-001.md) and the API [ADR-002](../../../prime-sweets-api/docs/adrs/ADR-002.md).

## Context

The API retires the Sales Day. Sales, Load Sheet, and invoices are all queried by delivery date. The current client home, routes, and hooks are built on Sales Day ids (`/day-sales/:id`, `useCurrentSalesDay`, open/close/reopen).

## Decision

| UI behavior | Module |
|---|---|
| Home with delivery-day strip and day actions | `sales` (delivery days are a sales concept now) |
| Sale capture, delivery date, correction, void | `sales` |
| Sales of a delivery day | `sales` |
| Load Sheet and invoices of a delivery day | `fulfillment-output` |

- The selected delivery day lives in the URL (`?deliveryDate=YYYY-MM-DD`) so every screen can be linked and reloaded. The shown week is derived from that date.
- Week navigation is client-side date arithmetic in `sales/domain/deliveryDays.ts`, for display only. Next week is capped at the current week. The API validates any date sent.
- `sales-day` is removed from the client: views, hooks, use cases, HTTP adapter, and dictionary strings.
- Invoice printing is driven by `deliveryDate`, not `salesDayId`.

## Rejected alternatives

### Keep `sales-day` as a hidden module that auto-opens the day

Rejected. It contradicts the API decision and keeps dead states on screen.

### A `returns` module

Rejected. A return is an edit or a void of the sale.

### Hiding edit actions on past days

Rejected. The business allows correcting a sale from any week.

## Consequences

- Routes `/sales-day`, `/day-sales`, `/day-sales/:id`, and `/invoices/:salesDayId/:saleId` are replaced by `/` (home), `/delivery-sales?deliveryDate=`, `/load-sheets?deliveryDate=`, and `/invoices/:saleId?deliveryDate=`.
- `useDraftSale` no longer checks an open day before creating.
- `CreateSale` stops sending `salesDayId`.
